# Handoff diagrams

`handoff-overview.drawio` is a single, 4-page draw.io file generated by
`gen_handoff_diagrams.py`:

1. Repo & Module Map
2. Build Option Flow
3. Benchmark & Design-Evidence Pipeline
4. Project Status Map

It's separate from `diagrams/UniQOS DB Architecture.drawio` at the repo
root (25 pages covering the database's internal data structures and
flows in detail) -- this file covers what that one doesn't: repo layout,
build options, the benchmark pipeline, and current project status.

## Editing

Either edit `handoff-overview.drawio` directly in the draw.io desktop
app/editor, or edit `gen_handoff_diagrams.py` and regenerate (preferred
for layout changes, since box positions are plain coordinates in the
script):

```sh
python3 gen_handoff_diagrams.py
```

## Exporting for the Typst docs

Typst's SVG support doesn't render draw.io's `foreignObject`-based text
labels (see <https://github.com/typst/typst/issues/1421> -- confirmed
during this doc set's own build: SVG export renders as solid colour
blocks with no visible text). **Export to PNG, not SVG**, for embedding:

```sh
mkdir -p png
names=(repo-module-map build-option-flow benchmark-pipeline project-status-map)
for i in 1 2 3 4; do
  drawio -x -f png -s 2 -p "$i" -o "png/${names[$((i-1))]}.png" handoff-overview.drawio
done
```

`-s 2` gives a 2x-scale render for print quality. The same caveat applies
to `diagrams/UniQOS DB Architecture.drawio` at the repo root -- its
`.svg` exports used by `README.md` have the same `foreignObject` issue
and were re-exported as PNG into `png/readme/` for use in
`docs/typst/01-architecture-overview.typ`:

```sh
cd ../../diagrams
drawio -x -f png -s 2 -p <page-index> -o "../docs/diagrams/png/readme/<name>.png" "UniQOS DB Architecture.drawio"
```

Page indices for the pages currently embedded: 3 relationalModel, 9
data_structs, 11 hash_table_reconstruct, 12 rollbackJournal, 13
msg_contact_access, 14 sd_layout, 15 free_list_stack, 16
tombstoning_solution. Re-check indices with `drawio -x -f xml
"UniQOS DB Architecture.drawio" -o -` (or just reopen the file) if pages
are added, removed or reordered.

Headless export needs no X server on this machine despite being an
Electron app -- it runs directly (`drawio -x ...`), no `xvfb-run` needed.
